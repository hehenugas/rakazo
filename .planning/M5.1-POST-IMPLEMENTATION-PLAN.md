## Phase 37 — Email retry correctness (P1)

**Observed:** `packages/adapters/src/draft-binding.ts:updateEmailDraftExecutionStatus` extracts draftId from source nonce but does not guard status updates against the *currently active* `executionAttempt`/run. An old worker could overwrite a new retry. Also `DraftActionCard.tsx` renders Discard on submitted+failed, while `discard()` exits if status !== draft.

- [x] **37-01 — Fence by attempt.** Parse original/retry nonce and bind every worker update to the active draft attempt (or explicit run identity). Reject previous-attempt callbacks before CAS. Preserve actor/thread/draft scope.
- [x] **37-02 — Define state progression.** `queued -> executing -> sent/failed/unknown` per attempt; stale queued/failed cannot overwrite a newer outcome. `unknown` must not be auto-retried without authoritative result.
- [x] **37-03 — Trace execution paths.** Inspect `executor.ts` structured email, connector fallback, external effects, approval pause/resume, crashed jobs, and `apps/api/src/draft-actions.ts` retry. Match all status writes to active attempt and provider receipt.
- [x] **37-04 — Fix dead Discard.** Only show Discard for editable draft. For submitted+failed, show functional Retry; optionally implement a *separate* server-authorized dismiss/archive action retaining the audit trail. Never silently discard a submitted action.
- [x] **37-05 — Receipt precision.** Review `packages/adapters/src/email-delivery-receipt.ts`: classify `sent` from provider-specific, genuinely successful send responses only; do not treat unrelated nested IDs as delivery confirmation. Ambiguous results => unknown, explicit errors => failed.
- [x] **37-06 — Web/mobile consistency.** Shared server lifecycle drives cards on web/Electron and mobile. A retry must keep frozen approved fields and the selected, validated connection.

**Acceptance via code review:** no old-attempt callback can change a newer attempt; delivered state is backed by provider receipt; no inert card actions.

## Phase 38 — Google Slides adapter, delivery status and artifact version (P1)

**Observed:** Pipedream `discoverTools()` returns *lazy catalog wrappers* when tool count exceeds `DIRECT_TOOL_LIMIT=20`, but Google Slides capability/execution looks for a real Markdown tool in that list. Deck cards fetch status only on mount/account change. Delivery status reader filters by artifact ID but not its current version.

- [x] **38-01 — Fix Pipedream tool resolution.** Lookup Google Slides tools via scoped raw `allTools(context)` or a dedicated concrete-tool resolver, not lazy wrappers. Use the same resolver for capability check and execution. Keep lazy catalog for agent discovery.
- [x] **38-02 — Account isolation.** Verify `route.resourceId`, connected account, ownership, scope, and connector selection for Composio/Pipedream. Missing capability => honest unsupported; do not use another user's connection or simulate delivery.
- [x] **38-03 — Version-scoped status.** In `apps/api/src/presentation-export.ts`, match `artifactDelivery` by actor, artifact ID, **current version**, account ID, and account snapshot. Earlier deck receipts must never label an edited version Delivered.
- [x] **38-04 — Refresh pending.** Web `DeckCard.tsx` and mobile `components/deck-card.tsx` should subscribe to server events or poll only during pending. Handle focus/reconnect, cleanup on unmount/account switch, ignore late responses, stop at terminal outcome.
- [x] **38-05 — Crash/unknown safety.** Inspect delivery claim, stale-pending reconciliation and retries. Never create a duplicate external presentation when outcome is uncertain; persist confirmed file ID/link and distinguish failed from unknown.
- [x] **38-06 — Accurate controls.** Button disabled/retry states follow server truth. A valid link only appears after real provider receipt; unsupported states remain truthful.

**Acceptance via code review:** works with large lazy catalogs and multiple accounts; old deck version cannot leak its receipt to the new version; pending status eventually refreshes without duplicate attempts.
