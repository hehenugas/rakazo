# Phase 17 — Experience Parity Contract & Journey Baseline

## Objective

Replace M2's pixel-oriented completion model with a current Grok Bot journey contract and produce an actionable gap matrix for phases 18–23.

## Scope

- current official Grok Bot docs/changelog refresh
- primary journeys and entry points
- terminology
- lifecycle/state semantics
- desktop/mobile split
- removal of pixel-diff requirements from future DONE gates
- reclassification of gaps that M2 incorrectly treated as pending-reference

## Required Journey Matrix

At minimum map:

1. create/open/edit/hide/share a Bot
2. create/manage/test/pause/delete a Routine
3. Team Bot create/copy/start-fresh/setup/publish/open/unpublish
4. composer lists, selection/add-to-prompt, attachments, voice, send/stop
5. failed-message retry/delete
6. approvals and credential handoff
7. Connect apps / plugin discovery and sign-in
8. voice memo playback/transcript
9. Project creation/planning/delegation/status/stop
10. Main Bot attention/proactivity
11. desktop/mobile differences

## Acceptance Criteria

Every P1 experience gap has an owning later phase. No item is marked pending-reference when current public official documentation already specifies the behavior.

## DONE Gate

Journey matrix, requirements, and M3 acceptance rules are current and phases 18–23 are ready to execute.
